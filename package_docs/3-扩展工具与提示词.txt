================================================================
  3 · 任务超出 7 个工具时：让 AI 帮你补「工具 + 提示词」
================================================================

【什么时候用】
  内置 7 个工具（shell / 读文件 / 找文件 / 写文件 / 改文件 / 搜索 / 抓网页）
  覆盖不了的任务，比如：Excel 汇总、Word 报告、PDF 提取、批量改图片；
  或者客户端装了技能（PPT / docx），想让 trim 用上。

【为什么不能随便加工具】
  模型靠名字调工具（<invoke name="Write">…</invoke>），网关把名字转给客户端后，
  客户端会拿自己的工具表严格校验。名字或参数对不上，整轮被拒，
  现象是「模型说做完了，但文件没出现」。所以客户端没有的工具，造出来也没用。

  这决定了补什么只有四种情况：
    A 客户端本来就有、只是清单没列     -> 补一条工具 JSON
    B 客户端根本没有（Excel/Word…）    -> 不造工具，shell 拼命令，写进提示词
    C 工具够用，只是缺做法             -> 只补提示词规则
    K 客户端装了技能                   -> 写一条「技能入口规则」，顶掉旧的土办法
  多数任务是 B + C 混合。

【三步】
  1) 复制下面的模板到任意会写代码的 AI（网页版 DeepSeek / 新开一个对话都行）。
     要填的只有五处，都标了「（提示：…）」，提示行不用删：
       客户端        -> 写 WorkBuddy 或 DSH
       上限          -> 抄「提示词」页底部「system 最大字符数」那个数字
       工具 JSON     -> 复制 trim「工具 (JSON)」页整段
       提示词        -> 复制 trim「提示词」页整段
       任务 / 期望产物 -> 自己一句话写清
     装了技能的，再多填一行技能目录，别的不填——技能怎么用由 AI 自己判断。
  2) 它只回两段：工具 JSON + 提示词规则，末尾带两行凭证：
       「需删除：…」    它指出哪几条旧规则该删（没有就写「无」）
       「字数：新增 N…」新增了多少字；模板把新增量硬顶在 600 字，超了会自己砍条数
  3) 贴回 trim：
       「工具 (JSON)」页  -> 整段替换成它给的完整数组 -> 点「校验并格式化」
       「提示词」页        -> 末尾(Ctrl+End) -> 换行 -> 粘贴它给的 9) 10) 那几行
                             （编号接着你现有最后一条往下排，不用自己改）
                             它写了「需删除」的，先删掉那几条再粘
       点「保存配置」-> 看到「网关热重载」即生效

【贴之前扫一眼这五点】
  - 输出里出现你没见过的工具名（比如 Excel）-> 客户端没有，让它「按 B 类重做」。
  - 它把整份提示词重写了一遍 -> 只要「二、提示词」那段，别整份覆盖，
    否则你原有的文档处理规则会被弄丢。
  - 规则里出现了这次任务的具体文件名（比如 D:\报告.docx）-> 让它改成
    「从我当次说的话里取」，否则下次换个文件就不管用了。
  - 技能规则和旧规则并存（比如同时有 COM 生成 pptx 和技能入口）->
    模型会在两条路之间反复横跳，必须二选一。
  - 粘完发现提示词末尾被截掉 -> 「提示词」页底部把 system 最大字符数改大
    （0 = 不截断），再点保存配置。

════════════ §1 环境（固定事实，勿质疑勿复述）════════════

· 网关只把「精简后的 system + 工具清单」发给上游，客户端自带的 system 通常被丢弃，
  你的依据只有 §3 和 §5，不要假设我看得到别的东西。
· 模型用 XML 调工具：<invoke name="工具名"><parameter name="参数名">值</parameter></invoke>
· 客户端按自己的 schema 校验工具名与参数名，对不上就整轮拒收，
  现象是「模型说做完了，但文件没出现」⇒ 严禁发明客户端没有的工具。

我不告诉你技能里写了什么，你按目录名和任务自己判断，必须做到：
· 入口规则：Glob `**/SKILL.md`（path 用我给的目录）→ 先看入口文件多大，
  超一次读取上限就用 Read 的 offset/limit 分段读完，别只看开头就动手。
· 只抄入口文件里的路由表，禁止把 references 正文搬进提示词；路径一律按当次
  Glob 结果写，绝不写死带版本号的完整目录。
· 技能里的外部工具名必须映射：write_to_file→Write（DSH 用 write），
  present_files / TaskCreate 跳过；bash 块改写成 PowerShell。
· 缺的能力：能用 shell 拼的就拼，能补工具的补工具。
· 必须带兜底：Glob 没命中所需技能就直接按库/shell 做，不要反复换目录找，
  也不要声称需要装技能。
· 命令不在 PATH 时给绝对路径兜底（WorkBuddy 形如 %USERPROFILE%\.workbuddy\
  binaries\node\versions\<版本>\<名>），并写明「先用 where 确认真实路径」。
· 与技能冲突的旧规则在 §9「需删除」里点名。

════════════ §6 先判断补什么 ════════════
A 客户端有这个工具、只是清单没列 → 补工具 JSON
B 客户端没有（Excel/Word/PDF/压缩/图像等）→ 不造工具，shell 拼命令写进提示词
C 工具够用、缺做法 → 只补提示词规则
K 装了技能 → 写技能入口规则（§5），并按需补工具
多为 B/C/K 混合。拿不准有没有某工具 → 按 B 处理。

════════════ §7 已验证的失败模式（写规则时必须规避）════════════
· 技能目录写死绝对路径 → 换机或升级即失效，只能写「按当次 Glob 结果」。
· SKILL.md 几十 KB 时单次读会被截断、只剩开头，模型于是自己乱猜路线。
· 生成 Office 产物优先用 pip 库（python-pptx / python-docx / openpyxl）；
  COM 要装 Office、易被安全策略拦、还慢，仅库不可用时才用。
· 工具名被拼两遍（PowerShellPowerShell）→ 参数全错、整轮白跑。
· 把报错文本粘进参数（file_path 变成 <system-reminder>…）→ 文件必然不存在。

════════════ §8 硬约束（违反任一条，输出即不可用）════════════
1  工具名、参数名、参数类型必须与客户端完全一致
2  现有工具一条不改，只在数组末尾追加
3  工具 JSON 输出完整新数组且是合法 JSON：无注释、无尾逗号、不写 "…"
4  工具 description 用英文，提示词规则用中文
5  新规则接续 §3 最后一条的编号（先数清现有到第几条，如到 8) 就从 9) 起）；
   只给新增几行，不重写已有条目、不输出整份提示词
6  新增总长 ≤ 600 字，且 ≤ §3 上限 − §3 现有字数 − 100，两者取小；字数按字符算
   （一个汉字算 1）。数不出现有字数就按 600 写，宁少不多；建议 4~6 条、每条一句。
   空间不够就砍条数，结尾写「预算超限，已砍至第 N 条」，不要建议我改上限
7  每条规则要可执行：工具名 + 参数名 + 具体命令 + 路径写法；禁「注意格式」类空话
8  碰中文路径或中文输出必须带 [Console]::OutputEncoding=[System.Text.Encoding]::UTF8
9  长文本落盘用 Write / Edit，不用 here-string
10 出现本环境没有的工具名必须给映射，bash 命令一律改写为 PowerShell
11 规则长期生效：不许写死本次任务的素材/产物路径或临时目录，只出现目录、参数名、
   命令，具体文件路径由你运行时从我当次说的话里取
