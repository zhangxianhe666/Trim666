ds-trim-gateway 使用说明（Windows）
====================================

这是一个"翻译器"：把客户端（WorkBuddy 或 DSH）发来的超长请求精简后转发给
本机 AFS，再把上游返回的 XML 转成标准工具调用。你不用懂原理，按下面三步走。


一、准备
--------
1. 先启动 AFS（另一个程序），默认监听 127.0.0.1:8080。
   确认它在跑：浏览器打开 http://127.0.0.1:8080/health 应返回 {"status":"running"}。
2. 本程序不需要安装 Python 或任何依赖，整个文件夹拷走就能用。
   建议放在一个**固定位置**（例如 D:\ds-gateway），别放在桌面或下载目录，
   因为配置文件就生成在这个文件夹里，删了程序配置也没了。


二、三步启动
------------
1. 双击 ds-trim-gateway.exe
2. 选客户端（最重要，见下）、确认上游地址和模型，点「保存配置」
3. 点「启动网关」，看到「运行中 · http://127.0.0.1:8001」就好了

窗口不要关，关了网关就停了。

窗口一共五个页签，需要改什么就去对应页签，改完点底部「保存配置」：
  基础       客户端、上游地址/Key/模型、端口、请求间隔、空响应冷却
  提示词     精简 system 的全文。可直接改，改完保存立即生效
  工具(JSON) 工具列表 JSON 直接编辑。「校验并格式化」会检查语法并告诉你
             有几个工具、叫什么；写错会弹窗指出第几行第几列
  上下文精简 工具历史轮数/单条截断/总字符预算、对话历史开关/条数/截断/总预算、
             日期注入、本地图片开关与张数、单轮最多工具调用、搜索代执行模式与抓取页数
  日志       实时日志

底部按钮：保存配置 / 启动网关 / 停止 / 重新载入 / 打开 config.json /
打开配置目录 / 打开日志。
「重新载入」用于：你在外面用记事本改了 config.json，想把它读回界面。

注意：保存时用的是**页签里当前的内容**，不会用预设把你的修改顶掉。
切换客户端时，如果你改过提示词或工具，会先问你要不要覆盖——选「否」就保留。


三、客户端怎么选
----------------
两个客户端暴露的工具名不一样，选错的现象是"工具调用总是失败"、
"让它看文件它说做不到"：

  你在用 WorkBuddy   → 选 WorkBuddy（PowerShell / Read / Write / Edit / Glob / WebSearch / WebFetch）
  你在用 DSH         → 选 DSH（pwsh / read / write / edit / glob / web_search / web_fetch）

不确定就各试一次：选错时窗口日志里会出现
  [警告] 客户端没有与 XXX 等价工具
选对后日志里是
  工具名适配: ... （按客户端实际声明）
——有「适配」也不一定是错的，那是网关在按客户端声明纠正名字，能跑就没事。

选完之后在客户端那边填：
  地址：http://127.0.0.1:8001/v1
  模型：跟窗口里"模型"那一栏填的一样


四、常见问题
------------
1. 上游返回 503 No available account for model: xxx
   模型名不对。点「列出上游模型」，从弹出来的列表里挑一个填进去。
   这个报错看着像账号问题，其实只是名字对不上（大小写敏感）。

2. 工具调用总是失败
   客户端选错了。改成另一个再点「保存配置」。

3. 图片识别没反应
   先看窗口日志里有没有这一行：
     🖼 本地图片 1 张 → 注入标记: ['C:\\...\\xxx.jpg']
   有 → 图已经交给上游了，问题在上游（需要 AFS 1.7.0 以上）。
   没有 → 网关没认出你在说哪张图，检查下面几点：
     · 图片必须是**这台机器硬盘上的文件**（在客户端里上传/拖进来的图，DSH 只会
       把文件名当文本发出来，不会把图片数据发过来，所以文件必须落地在本机）
     · 在本轮消息里重新 @ 一次那个文件（上一轮 @ 过的不算，只认当前这一轮）
     · 文件名带逗号、空格、&= 都可以，网关支持
   另外要注意：DSH 每次提问后还会追加「运行时上下文/时间上下文」，网关会把它们
   当噪音剔掉；新版已经修好，如果日志里"当前问题"变成了 English 的
   "Time sampled while preparing…"，说明用的还是旧 exe。

   命令行方式后台常驻（不弹窗口，可配合开机自启）：
     ds-trim-gateway.exe --serve --port 8001

4. 搜不到东西 / 查天气、股价、新闻时它凭空说
   这是 DSH 的通病，不是网关坏了：DSH 的 web_search 不是本地工具，是客户端插件
   拿客户端自己的 DeepSeek API Key 直连 api.deepseek.com。Key 失效就固定返回
   HTTP 401，而且这条路**绕开了网关**，改提示词没用。
   现在的网关会接手：模型要搜索时，网关自己搜（必应）并抓回网页正文，再让模型
   照真实数据作答。日志里能看到：
     🔎 网关代搜: ['重庆今天天气']
     🔎 代搜完成: 2492 字符（含网页正文）
     🔁 第 1 轮代搜完成，把结果交给模型重答
   如果看不到 🔎，去「上下文精简 → 搜索」把模式改成
   「总是由网关代搜」，保存后重问一次。

5. 端口被占用 / 启动失败
   把端口改成 8002，然后在客户端里把地址同步改成 :8002。
   最常见的原因其实是**已经有一个网关在跑了**（比如之前用 python 启动的，
   或者上次没关窗口）。在任务管理器里结束所有 ds-trim-gateway.exe 再启动。

6. 双击没反应
   同目录下会生成 launcher-error.log，把它发给维护的人。

7. 想看得更细
   点「打开日志」。每次请求会记：客户端工具列表、精简后长度、是否注入图片、
   工具名适配过程、是否代搜、上游状态码。


五、文件说明
------------
ds-trim-gateway.exe   主程序，双击运行
config.json           配置（首次保存时生成，可备份/拷贝）
launcher-error.log    只有崩溃时才出现
