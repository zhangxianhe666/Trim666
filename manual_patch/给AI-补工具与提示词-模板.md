# 给 AI 的配置模板（最终版）

> 模板正文：`最终版-补工具与技能-模板.txt`（3112 字 / 107 行 / 9 节）
> 分发包里已带：`package_docs/3-扩展工具与提示词.txt`
> 旧的两份（极简版 / 完整版）已归档到 `旧版/`。

## 用户只做五件事

打开模板 → 填五处 → 丢给任意 AI → 拿回两段 → 贴回 trim。

| 要填的 | 从哪来 |
|---|---|
| 客户端 | 写 `WorkBuddy` 或 `DSH` |
| `上限 =` | trim「提示词」页底部「system 最大字符数」那个数字 |
| 工具 JSON | 复制「工具 (JSON)」页整段 |
| 提示词 | 复制「提示词」页整段 |
| 任务 / 期望产物 | 一句话自己写，技能目录装了才填 |

提示行不用删，留在原处即可——模板要求 AI「取看我写在它下面那几行」，
所以提示行和答案共存不冲突。

## 输出只有两段 + 两行凭证

```
## 一、工具 JSON      -> 整段替换「工具 (JSON)」页
## 二、提示词          -> 粘到「提示词」页末尾
需删除：逐条列出 / 无
字数：新增 N（system 上限 M / 现有 K / 剩余 M−K）
```

`需删除` 不是可选项：技能规则与旧的 Excel/COM 规则并存时，模型会在两条路
之间反复横跳。让 AI 自己过一遍、点名第几条，用户照删即可。

## 这版撑住「通用」的四根柱子

**① 零硬编码。** 模板里不出现任何本机的条数、字数、路径。「现有到第 8 条
就从 9) 起」「上限 3000」这类值全部改成 AI 从 §3 自己数。校验脚本
`check_template.py` 会扫描 `37806` / `1195` / `2000` / `7 条` 这类字样，出现即报错。

**② 600 字硬顶。** 新增总长取 `min(600, 上限 − 现有 − 100)`。因为 AI 数现有
字数并不可靠（实测有一轮把 1716 数成 1280，于是以为还剩 1620，写了 1342 字，
实际已超 3000 上限，粘进去末尾会被静默截断）。600 这个绝对硬顶让它**数错也安全**：
1716 + 600 = 2316，远低于 3000。

**③ 示例不等于取值。** 提示行里的「例如 C:\Users\你\…」曾被一个执行者当成
真实路径直接抄进规则。开头因此明确：提示行是说明，取值在它下面那几行，
`例如…` 永远只是示范。

**④ 规则不许带本次任务的路径。** 第一版测试产出的规则里写死了
`D:\报告.docx`，下次换文件即失效。constraint 11 已禁止，实测两轮均遵守
（改为 `sys.argv` 传参、或写「从我当次说的话里取」）。

## 六轮实测记录

每轮把模板按真实运行配置填满（`gen_test_filled.py` 可重建这份输入），
交给互不知情的执行者，只看它产出的配置能不能直接用。

| 轮 | 结果 | 暴露的问题 → 修法 |
|---|---|---|
| 1 | 产出可用 | 把提示行的示例路径当答案抄走 → 加「示例只是示范」 |
| 2 | 两段齐全，编号 9) 正确 | 规则写死 `D:\报告.docx`；删条目后断号 → 加约束 11、加顺延说明 |
| 3 | 两者都遵守路径约束 | 都没写「技能目录没命中怎么办」，会卡在 Glob → 加兜底要求 |
| 4 | 结构稳定 | 现有字数数成 1280 导致超预算；`需删除` 判成「无」→ 加 600 硬顶、需删除改逐条强制 |
| 5 | 精确指出两处空、拒绝猜 | 填充脚本没跟上模板措辞（非模板问题），反证「空着就问」有效 |
| 6 | 新增 580 ≤ 600；删除列出 4 条；字数三数正确 | 稳定，无新问题 |

判定标准不是「能不能生成」，而是：两段齐全、编号接续现有最后一条、
`新增：无`（不发明工具）、规则里无本次任务路径、新增 ≤ 600、`需删除` 有具体条目。
第 6 轮全部命中。

## §7 那五条为什么值得占篇幅

它们不是凭空写的，是从真实失败的会话日志里挖出来的，每条都对应一次实际浪费：

| 失败模式 | 实际代价 |
|---|---|
| 技能目录写死绝对路径 | 换机 / 升级即失效 |
| SKILL.md 单次读被截断 | 21KB 的入口只读到 37%，模型拿不到做法，自己 `pip install` 试了 30 次 |
| 用 COM 而非 pip 库 | COM 要装 Office、易被安全策略拦、还慢 |
| 工具名被拼两遍 | `PowerShellPowerShell`，参数全错、整轮白跑 |
| 报错文本粘进参数 | `file_path` 变成一段 `<system-reminder>…`，必然 ENOENT |

## 一个仍然存在的限制

600 字装不下很复杂的任务。遇到这种情况，模板会让 AI 砍条数并写
「预算超限，已砍至第 N 条」——**分两轮补**：先补最关键的 4~6 条，
跑通后再来一轮补边缘情况。这比一次性塞满然后被 system 截断要好。
